# 接入大模型分析页面：可行，但**不该用来做主力提取**

> 2026-10-31　全部数据来自本机 Ollama 实测（qwen3.5:2b / qwen3.5:9b）

## 一、结论

| 用途 | 可行性 | 建议 |
|---|---|---|
| **主力提取商品列表** | ❌ 不可行 | 速度和准确率都撑不住真实页面规模 |
| **兜底：正则全挂时救场** | ✅ 可行 | 只在页面解析为 0 条时触发，值得做 |
| **辅助判断：这是商品卡还是广告位** | ✅ 可行 | 小批量分类，延迟可接受 |
| **SKU 规格归一化** | ✅ 可行 | 输入小（几十个规格名），收益大 |
| **替代选择器维护** | 🔶 部分可行 | 页面改版时用它临时兜底，不是长期方案 |

## 二、实测数据（这是判断依据）

### 准确率随规模断崖下跌

| 商品数 | 文本长度 | 2b 耗时 | 2b 准确 | 9b 耗时 | 9b 准确 |
|---|---|---|---|---|---|
| 10 | 514 字 | 3.4s | **10/10** | 7.1s | **10/10** |
| 20 | 1022 字 | 7.1s | **20/20** | 14.9s | **20/20** |
| 40 | 2038 字 | 12.3s | **0/40 ❌** | 24.9s | **32/40 ⚠️** |

- **2b 在 40 条时完全崩掉**（输出被 `num_predict` 截断，一条都没解析出来）
- **9b 在 40 条时也只抽到 32/40**（漏 8 条，没有报错，静默丢失）
- 耗时**严格线性**：约 0.6 秒/条

### 真实页面规模外推

PDD 实测 `inner_text` 是 **5394 字、约 75 个商品**。按上表比例：

- 2b：75 条约 **23 秒**，但 40 条就崩，**不可用**
- 9b：75 条约 **47 秒**，且预计漏 15-20%

而**现在正则方案处理整页只要 0.1 秒，准确率 75/75。**

### 另一个坑：模型是思考型

`qwen3.5` 默认把内容写进 `thinking` 字段，`response` 为空。必须：
- 传 `"think": false`，或
- prompt 加 `/no_think`
- 否则拿到的 `response` 是空字符串，看起来像"模型没输出"

这个坑我踩了两次才发现。

## 三、真正值得接的场景（按性价比）

### ✅ 1. 解析失败兜底（收益最高）

现在 `collector.collect()` 在解析不到商品时，只会：
1. 截图
2. 写诊断文件
3. 返回 `error`

**改成**：先试正则 → 若 0 条，把页面 `inner_text` 前 2000 字喂给 9b，
让模型尽力抽。哪怕只抽到 5 条也比 0 条强。

- 触发条件严格：只在 `items == 0` 时调，正常采集零开销
- 成本：单次 ~8 秒，可接受（反正那一轮本来就要失败）
- 用 9b 不用 2b（2b 价格全填 0，实测）

### ✅ 2. 规格名归一化（收益大、输入小）

`repricing.sku_spec_key()` 现在纯靠正则解析 SKU 名。
遇到 `"8GB DDR4 3200 C16战斧马甲"`、`"16GB（8G*2)DDR4 3600 C18"` 这类时，
正则能处理；但遇到更乱的（`"DDR4 8/16G 全兼容 海力士A-die"`）会出错。

**改成**：正则先跑；拿不准的（`cap` 或 `count` 缺失）再让 9b 判断。
输入只有一行规格名，**~1 秒/条**，准确率高。

### ✅ 3. 商品卡 vs 广告位判别

PDD/JD 页面混着推荐位、广告位、榜单卡片。
正则用「恰好一个 ¥ + 有图」过滤，仍有漏网。

**改成**：对边界情况（标题极短、价格异常低）让 2b 二分类判断。
输入小、任务简单，2b 够用且快（~1 秒）。

### 🔶 4. 页面改版时的结构理解（一次性）

当某平台改版、选择器全失效时，可以让 9b 看页面结构片段，
帮你**推测新的选择器**（不是运行时调用，是开发时辅助）。
这个价值高但不能常态化。

## 四、明确不该做的

- ❌ **不要用它替代 `EXTRACT_JS`**：慢 500 倍，还会静默漏条目
- ❌ **不要在每轮采集都调**：一次 8-50 秒，三个平台三轮就是几分钟
- ❌ **不要用 2b 做数值抽取**：实测价格全部填 0
- ❌ **不要指望它稳定**：40 条就崩，没法当成可靠组件

## 五、如果要落地，接口设计

```python
# llm_extract.py
def assist_extract(page_text, want="items", model="qwen3.5:9b", timeout=20):
    """仅作兜底。调用方负责保证：只在正则失败时调用、文本已截断到 2000 字。"""
```

三条硬约束：
1. **只在失败时调用**（`items == 0`），正常路径零开销
2. **文本先截断到 2000 字**（超过就分片，别指望一次抽完）
3. **结果必须清洗**：价格非数字、标题过短的直接丢
4. **加超时**（20 秒），超时就放弃 —— 不能让它拖住采集（详情页的教训）

## 六、一句话总结

**本地小模型能用，但只能当"兜底"和"辅助判断"，不能当主力。**
现在正则 0.1 秒抽 75 条全对，模型 47 秒抽 60 条还漏 —— 主力提取这条路上，
正则仍然完胜。真正该接的是「正则挂了时的救场」和「规格名归一化」这两个小切口。
